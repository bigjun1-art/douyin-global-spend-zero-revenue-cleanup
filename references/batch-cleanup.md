# 旧全域批量清理：路由、页面操作与验收

## 入口与授权

- 沿用本任务已明确的账户、计划、统计区间、保护条件和删除授权，不为同一清单逐批再次询问。范围改变或工具强制审批时才重新处理授权。
- 先读取本任务检查点；用户提到历史成功时，查实际调用和回读证据，区分官方 MAPI、页面登录态接口和正常 UI 操作，不只看历史回复中的名称。
- 官方 MAPI 用最小只读请求验证准确计划及完整素材映射。旧 ROI2 URL 的 adId 不一定是官方 promotion_id/project_id；仅用真实响应取得映射，不猜 ID。账户报告成功或空计划报告都不能证明计划无素材或具备删除能力。已确认不覆盖后，无新证据不重复探测同一路径。
- MAPI 查询＋UI 提交须如实称为混合流程。页面接口成功不能称为官方 MAPI 删除成功。发生任何写入后，先对未决结果完成回读，再决定后续执行方式。
- 页面接口明确返回 40010 等禁止调用说明时，停止该接口路径，不绕过。429、超时或不明写入结果不得自动重发；只能先读回准确 ID 状态。
- 浏览器使用当前可用且已授权的入口。macOS 已授权 AppleScript 时，直接使用 `/usr/bin/osascript <任务内脚本文件>`，不要仅为包装同一操作反复引入需新审批的解释器。不得改变权限、接管审批弹窗或规避真实审批。

## 日期、近期保护与候选清单

- 把近 N 天转换为明确起止日期，核对页面实际值；快捷日期可能与预期不同。滚动小时和自然日保护需按用户口径确定，不将本次近 30 天、近 3 天变成所有任务默认值。
- “最近加入计划”不能仅用视频发布时间、上传时间或素材 createTime 代替。优先用计划添加时间或成功添加记录与准确 ID 映射；字段含义不明、加入时间缺失的素材保留并说明。历史截图只能证明其可见内容，不能据少量缩略图断言整批 ID。
- 保护清单同时从删除候选和首次观察清单中排除。每个 ID 都保留字符串格式；缺失指标、显示四舍五入为 0.00 的微小正数不能判为精确零。
- 按对应技能规则用精确数值生成本次批准 ID 清单，并保存账户、计划、区间、保护依据和原始 ID 集合。删除前实时复核；变化时缩小范围，不自动扩大已批准集合。
- 原有直接接口 runner 不支持近期添加保护参数。任务要求保护时，不直接按文末旧命令执行全量候选；先落实保护和批准 ID 约束，再使用本流程。不要声称传入了脚本未实现的参数。

## 正常页面批量操作

仅在页面结构实测一致时采用这些定位线索；不得复制旧窗口序号、标签序号或账户 ID。

1. 锁定 Chrome 资料与完整 URL，并核对素材面板中的准确计划 ID、标题、统计日期。管理页 URL 可能只有 advid，仍必须核对面板目标。每次脚本运行重新确认目标；只有一个执行者。不保存另一编辑页的未提交修改。
2. 门店 ROI2 实测素材行是 `tr.roi2_creative_table_row`，行内 `[legomaterialid]` 是素材 ID，复选框是 `input[type=checkbox]`。先用准确 ID 定位行，再读取该行；列位置和指标含义需从实时表头确认。
3. 翻页/刷新会改变行顺序。等待目标页与 ID 集合稳定，不重复使用旧 AX 索引或一次快照中的所有坐标。工具栏清空后勾选框可能残留旧状态；翻页返回并确认清单和工具栏都清空后再选。
4. 页面当次实测上限为 50 条/批，应遵守实时上限。顺序触发正常勾选操作并等待渲染，用**无序 ID 集合**比较“批准的本批 ID”“真正勾选的行”和工具栏数量；不能只比较顺序、数量、input.checked 或 AX 0/1。任一不一致先停在未提交状态，清除选择并重新核对。
5. 批量素材“删除”可能是工具栏中的可见 `span`。同页可能有隐藏的计划删除按钮且共用 `data-auto-id`；严禁直接点全页面第一个删除按钮。定位到素材工具栏，并核对可见确认框明确写“所选的 N 个素材”。“N 个计划”、数量不符或多个可见确认框一律取消，不提交。
6. 提交前保存 pendingBatch ID、当前完整 ID 集合和时间；提交只执行一次。每批通过回读后立即将具体 ID 写入本地检查点，不能只存在浏览器变量中。跨轮恢复以检查点和最新列表为准，排除已确认删除的 ID。

## 回读与恢复

- UI 成功提示、单页看不到素材、缓存总数变化，都不单独作为删除成功证据。优先读取仍允许使用的完整计划素材列表；否则完整遍历刷新后的 UI 分页。受限制的接口不作为替代通道。
- ROI2 已验证列表结构包含 `data.materials.videoMaterial`、`data.materials.materialStatsMap` 和 `data.pagination`。精确指标可能仅在 statsMap 中，必须按字符串 ID 合并再判断。响应中的汇总行不能计入素材；有效素材数应与服务端 totalNum 一致，分页覆盖完整。
- 总数变化滞后时先做只读刷新，核对本批准确 ID。结果仍不明就标记 pending，禁止自动重发该批。确认不存在后补记成功；确认仍存在也应记录未完成并重新审查当前范围，不能盲目重试。
- 最终核对：删除 ID 全部不存在；原始集合的缺失 ID 与批准且已提交的 ID 完全相等；保护集合无缺失；非目标规则删除数为 0；并复查管理页准确计划仍在预期状态、无残留选择。
- 可用 `scripts/verify_cleanup.mjs <核验输入.json>` 做离线集合核验。输入包含 `beforeIds`、`afterIds`、`approvedIds`、`protectedIds`、`afterTotal`，所有 ID 为非空数字字符串；`afterTotal` 是完整服务端总数。该工具只核验集合，不能证明账户、计划、统计指标或保护时间正确。

## 有消耗零产出观察

两次观察必须是同一 surface + planId 的独立成功运行，不能把本次预览、分页或重跑当作第二次。旧账本属于另一计划则不可复用，也不可覆盖丢失。首次观察只在最新指标和完整 ID 回读通过后提交；使用独立计划账本或保留多计划记录，交付时明确账本路径。已授权范围内不要求用户对每次观察再次确认。
